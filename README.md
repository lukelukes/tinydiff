# tinydiff

A desktop application to view Git diffs and perform GitHub style code reviews. The GUI is an Electron app with a React renderer talking to the Rust core through an N-API addon.

## Development

- `just gui::dev <path>` runs the app against a repository with hot reload.
- `bun validate` formats, lints, typechecks, builds, and runs the unit, property, and browser tests.
- `just gui::e2e` builds the app and runs the Electron end-to-end suite.

## Packaging

`just gui::package` builds the renderer, main, and preload bundles, then produces `release/TinyDiff-<version>-x86_64.AppImage` and `release/TinyDiff-<version>-amd64.deb` with electron-builder, configured in `electron-builder.json`. The N-API addon ships unpacked next to the asar under `resources/app.asar.unpacked/out/main/chunks/`. Packaging only succeeds once the `packaged` Vitest project has read the artifacts back with `e2e/packaged-artifacts.spec.ts`: no binary in either artifact may need a `GLIBC_` symbol newer than the supported baseline, the deb has to declare that baseline as its `libc6` minimum, both executables have to carry the fuses `electron-builder.json` configures, neither launcher may disable the sandbox, and the sandbox helper policy the deb ships has to pick the right mode for each kernel configuration. The artifact names come from `electron-builder.json`, `package.json`, and the host architecture (x64 or arm64), and a missing artifact fails the run.

`just gui::e2e-package` runs the end-to-end suite against a temporary copy of the unpacked build for the host architecture with only the Node CLI inspect fuse re-enabled. `just gui::smoke` runs `e2e/smoke.sh` against the untouched AppImage and the executable extracted from the deb, each in its own `xvfb-run -a` server with `--ozone-platform=x11`, so it behaves the same in an X11 session, a Wayland session, and on a headless machine. The script creates a temporary repository, waits for the window, fails if the window process runs with `--no-sandbox`, and requires a clean exit on `SIGTERM` within ten seconds without a Chromium `FATAL` line.

`just gui::deb-install` installs the deb with `apt` inside the pinned `debian:13-slim` image, so the packaging is checked against a clean supported distribution rather than against the build host; it needs Docker and a network connection. It checks that every shipped binary resolves each of its libraries before any test tooling is installed, that the installer leaves the sandbox helper setuid exactly when an unprivileged user in that container cannot create a user namespace, and that `e2e/smoke.sh` starts the installed app as an unprivileged user. It relaxes the default seccomp profile of the container because Docker blocks the unprivileged user namespaces that a desktop grants, and Chromium would otherwise look for the setuid helper that the installer leaves out wherever those namespaces work.

Electron ships prebuilt binaries that the exact `electron` version pins, so only the addon is compiled here and the glibc of the build host sets the floor for both artifacts; the addon also links the vendored libgit2 and OpenSSL that the Rust core builds from source. The supported baseline is **glibc 2.38** (Debian 13, Ubuntu 24.04, Fedora 39 or newer). The deb declares `libc6 (>= 2.38)`, so `apt` refuses an install that could not start; the AppImage carries no metadata, so check `ldd --version` before running it on an older distribution. Nothing pins the glibc of the build host, so packaging enforces the baseline instead: a host whose toolchain links a newer symbol into the addon fails `just gui::package` rather than shipping a package that lies about its requirements.

The AppImage relies on Chromium's sandbox. electron-builder has no option for a custom AppImage launcher, so `electron-builder.json` copies `build/AppRun` into the app directory, where it overwrites the generated launcher that would otherwise pass `--no-sandbox` whenever unprivileged user namespaces look unavailable. Because that copy lands in every Linux target, the deb drops it again with an fpm `--exclude` of `opt/TinyDiff/AppRun`; renaming the product means updating that path, and the artifact check fails until it matches. `appImage.executableArgs` is empty because electron-builder otherwise writes `--no-sandbox` into the desktop entry. On distributions that restrict unprivileged user namespaces, extract the AppImage (`./TinyDiff-<version>-x86_64.AppImage --appimage-extract`) and make the bundled helper setuid root (`chown root:root squashfs-root/chrome-sandbox && chmod 4755 squashfs-root/chrome-sandbox`) instead of launching with `--no-sandbox`.

The deb makes that decision on install. `build/after-install.tpl` replaces electron-builder's `unshare --user` probe: that probe runs as root, and root is exempt from `kernel.unprivileged_userns_clone`, so it reported working namespaces on the very systems where ordinary users have none. The installer instead runs `build/sandbox-helper-mode.sh`, which ships under `resources/` and takes the `/proc` root as its argument. It reads `kernel.unprivileged_userns_clone` and `user.max_user_namespaces` and prints `4755`, a setuid helper, whenever user namespaces are missing, disabled, or limited to zero.
