# tinydiff

A desktop application to view Git diffs and perform GitHub style code reviews. The GUI is an Electron app with a React renderer talking to the Rust core through an N-API addon.

## Development

- `just gui::dev <path>` runs the app against a repository with hot reload.
- `bun validate` formats, lints, typechecks, builds, and runs the unit, property, and browser tests.
- `just gui::e2e` builds the app and runs the Electron end-to-end suite.

## Packaging

`just gui::package` builds the renderer, main, and preload bundles, then produces `release/TinyDiff-<version>-x86_64.AppImage` and `release/TinyDiff-<version>-amd64.deb` with electron-builder. The N-API addon ships unpacked next to the asar under `resources/app.asar.unpacked/out/main/chunks/`. Packaging only succeeds once `e2e/packaged-artifacts.spec.ts` has read the artifacts back: it takes the highest `GLIBC_` symbol version out of every binary in both of them, requires it to stay at the supported baseline, requires the deb to declare the matching `libc6` minimum, and checks that neither launcher can disable the sandbox.

`just gui::e2e-package` runs the end-to-end suite against the unpacked build for the host architecture, `release/linux-unpacked/tinydiff` on x86_64 and `release/linux-arm64-unpacked/tinydiff` on arm64. The suite first checks that the packaged binary ships with the hardening fuses set, then works on a temporary copy with only the Node CLI inspect fuse re-enabled. `just gui::smoke` launches the untouched AppImage and the binary extracted from the deb against a temporary repository, waits for the window, and checks that each exits cleanly on `SIGTERM` with the sandbox on. It runs in its own `xvfb-run -a` server and starts both artifacts with `--ozone-platform=x11`, so it behaves the same in an X11 session, a Wayland session, and on a headless machine.

`just gui::deb-install` installs the deb with `apt` inside the pinned `debian:13-slim` image, so the packaging is checked against a clean supported distribution rather than against the build host; it needs Docker and a network connection. The check requires that every shipped binary resolves each of its libraries from the declared dependencies, that the install leaves the sandbox helper in the mode the kernel policy of that machine calls for, and that the installed app starts for an unprivileged user with the sandbox on and exits cleanly on `SIGTERM`. It relaxes the default seccomp profile of the container because Docker blocks the unprivileged user namespaces that a desktop grants, and Chromium would otherwise look for the setuid helper that the installer leaves out wherever those namespaces work.

Electron ships prebuilt binaries that the exact `electron` version pins, so only the addon is compiled here and the glibc of the build host sets the floor for both artifacts; the addon also links the vendored libgit2 and OpenSSL that the Rust core builds from source. The supported baseline is **glibc 2.38** (Debian 13, Ubuntu 24.04, Fedora 39 or newer). The deb declares `libc6 (>= 2.38)`, so `apt` refuses an install that could not start; the AppImage carries no metadata, so check `ldd --version` before running it on an older distribution. Nothing pins the glibc of the build host, so packaging enforces the baseline instead: a host whose toolchain links a newer symbol into the addon fails `just gui::package` rather than shipping a package that lies about its requirements.

The AppImage relies on Chromium's sandbox. `build/AppRun` replaces electron-builder's launcher, which would otherwise pass `--no-sandbox` whenever unprivileged user namespaces look unavailable. On distributions that restrict them, extract the AppImage (`./TinyDiff-<version>-x86_64.AppImage --appimage-extract`) and make the bundled helper setuid root (`chown root:root squashfs-root/chrome-sandbox && chmod 4755 squashfs-root/chrome-sandbox`) instead of launching with `--no-sandbox`. The deb does this on install through `build/after-install.tpl`, which replaces electron-builder's `unshare --user` probe: that probe runs as root, and root is exempt from `kernel.unprivileged_userns_clone`, so it reported working namespaces on the very systems where ordinary users have none. The replacement reads `kernel.unprivileged_userns_clone` and `user.max_user_namespaces` instead and falls back to the setuid helper whenever they are missing or disabled. `just gui::deb-install` runs that script as the real postinst of a real install.
